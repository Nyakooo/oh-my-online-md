# 个人离线笔记与同步实施计划

用途是个人使用，不引入多人协作、账号体系或实时协同编辑。

## 第一阶段：独立本地工作空间（已完成）

- 插件无需后端即可打开本地笔记。
- IndexedDB 持久化正文、文件夹、排序、Blob 图片。
- 本地与服务器工作空间明确隔离；切换前处理未保存内容。
- 多窗口通过版本检查防止旧版本覆盖。
- 完整备份包含已保存笔记、文件夹、排序和附件；追加导入不覆盖笔记，失败整体回滚。
- 限制本地总容量 200 MiB、单图 10 MiB、正文 16 MiB，不支持分享和密码文件夹。
- 本机后端可绑定 127.0.0.1，默认工作目录下创建 data，日志显示绝对路径。
- 保持现有在线模式兼容。

## 第二阶段：本地导入服务器（已完成）

- 用户明确选择导入范围后上传，不因模式切换自动上传。
- 为创建及附件上传设计幂等标识与可恢复进度，避免网络超时后重复导入。
- 先上传附件再提交正文，失败保留本地原件和待重试状态。
- 记录目标服务器身份与笔记映射，禁止跨服务器复用进度。

## 第三阶段：服务器工作空间断线编辑与双向同步

- 每个服务器独立的 IndexedDB 缓存、同步基线和持久化操作队列。
- 保留服务端版本校验，不依赖设备时间戳决定覆盖。
- 单边修改上传或下载；双方修改保留冲突副本，用户处理。
- 持久化删除标记；删除与修改冲突保留修改，避免静默丢失。
- 明确文件夹重命名、移动、排序及图片清理的同步规则。
- 第一版不缓存受保护文件夹；后续如需离线访问，单独设计加密及解锁。
- 插件关闭、重启、断网、上传成功但响应丢失等情况下能够恢复同步。

当前支持独立离线笔记与用户选择后的单向导入，不提供服务器笔记的断线编辑或双向同步。导入后本地发生新修改，再次导入会创建新的服务器副本，不更新原副本。


第二阶段采用每篇笔记的原子导入：插件 IndexedDB 持久化按服务器地址、服务器身份、本地笔记 ID、版本与文件夹隔离的进度；服务端将正文与全部图片暂存，验证后原子发布目录，并把导入摘要与笔记一起保存。响应丢失后重试同一导入 ID 返回原结果，不覆盖服务器后续编辑。服务器数据目录中的 `.server-id` 持久化目标身份。
